# Port notes: VexFlow 5.4.0 → 5.6.1 (5.5.0, 5.6.0, 5.6.1)

Upstream range: `git -C ../vexflow log 5.4.0..5.6.1` (release notes: `changelog/CHANGELOG.md`, sections 5.5.0, 5.6.0 and 5.6.1).
The three releases are ported in one pass. 28 files in `src/` changed (+575/-169). There is no new module.
The manifest (`docs/porting-5.x-manifest.md`) now gives the Swift file for each upstream file of these releases.

## 5.5.0

- `continuousspan.ts` → `Layout/ContinuousSpan.swift`: `ContinuousSpan.labelFontSize` (points). `spanLabel(_:)` applies it to the label before the system breaks are chosen.
- `publication.ts` → `Publication/Publication.swift`: `PublicationOptions.noteHooks: [CommitHook]`. Each independently composed view (the reference score, the projected part and each cue or ossia inset) adds the hooks to its `EasyScore` before `compose`.
- `publication.ts` `inkBox()` → `Publication/SVGInk.swift` `svgInkBox(_:)`: an element with `opacity="0"` (the invisible pointer rectangles) has no ink, so it cannot move a note to another system.

## 5.6.0

Text defaults (`Core/Metrics.swift`, identical to upstream `MetricsDefaults`):
- `ChordSymbol.fontSize` 12 → 14; new `Annotation.lyric` (12 pt) and `Annotation.guitarStroke` (11 pt); `TabNote.text` 9 → 11 pt; `Stroke.text` 10 → 11 pt; new `TabTie.techniqueLetter` (bold 11 pt Arial); new `FretDiagram` category (9 pt).
- `Metrics.clear(key)` also clears the cached nested roles of `key` (for example `Annotation.lyric`).

Tablature:
- `TabNote`: the frets straddle the tick. `updateWidth` reserves half the fret width on each side (`setLeftDisplacedHeadPx`, `setRightDisplacedHeadPx`). `getModifierStartXY` uses `getTieLeftX()` / `getTieRightX()` for left and right modifiers and the tick x for the others.
- `GraceNoteGroup`: a before-grace group on a tab note clears the left half of the host fret.
- `Stroke`: on a tab note the arrow moves left by `NoteHead.minPadding`.
- `Annotation`: on a tab note the stacking above an up-stem uses the string spacing.
- `TabTie`: a one-letter technique text (for example `H`, `P`) uses `TabTie.techniqueLetter`.
- `GuitarModifiers`: the stroke finger label uses `Annotation.guitarStroke`.
- `StaveTie.renderTieText`: measures the text in the tie font, between `save()` and `restore()`.

Notes and rests:
- `Note.writtenDots`: the augmentation dots of the written duration.
- `StaveNoteStruct.restLine`, `StaveNote.restLine` and `StaveNote.setRestLine(_:) throws`: an explicit rest position. `nil` releases it and restores the previous automatic line. `StaveNote.format` moves only automatic rests when a voice has a pinned rest, then uses the column layout. `Formatter.AlignRestsToNotes`, `PhraseLayout` (pinned rests are placed first and never moved; `resetPlacement` keeps them) and `ContinuousLayout` (a pinned rest is not a plain rest and keeps its staff visible) respect it.
- `NoteHead`: the whole and half rest ledger glyphs follow the actual line on the attached stave (`updateRestGlyph`, also after `setLine` and `setStave`). `glyphProps.codeHead` stays the plain glyph. A custom glyph is kept.
- `StaveNote`: Bravura rhythm slashes (`noteheadSlashVerticalEnds`, `noteheadSlashWhiteHalf`) use the SMuFL `stemUpSE` / `stemDownNW` anchors when Bravura is the first family of the note font. Explicit `EngravingProfile` metadata still wins.

Other modules:
- `StaveSection`: `getBoundingBox()` gives the frame (ink plus padding) before drawing. `draw()` strokes that frame and renders the text at its own position.
- `Factory.ChordSymbol`: each given font field overrides only that field, so a custom family keeps the score chord size.
- `FretDiagram`: category `FretDiagram`; the start-fret label uses the element font.
- `SVGRenderContext.save()/restore()`: `getFont()` returns the font of the matching `save()`.
- `Stave.setBoundaryModifiers(_:notePadding:)`: extra space after the row-start signs. `ContinuousLayout` gives 1.5 spaces when a tab tie arrives at the first note of a continuation row.

EasyScore composition (`API/EasyScore/Composition.swift`):
- `showTimeSignature` on `EasyScoreStaffState`, `EasyScoreStaveSpec` and `EasyScoreMeasureSpec`: a hidden meter keeps its timing. Signatures, inline meter changes, the continuous-layout courtesy meter and the publication inset follow it.
- `EasyScoreMeasureSpec.endBarline`, `chords: [EasyScoreLeadMark]` and `verses: [[EasyScoreLyricMark]]`: chord names (an `Annotation` in the `ChordSymbol` font on one phrase lane per stave) and lyric verses (`PhraseLayout.addVerse`).
- Typed notes and rhythmic tab (`drawStem: true`) get their written dots (one dot per head for staff notes, one at the stem for tab).
- A failed composition removes the modifiers that it attached to a caller-owned native note.

Continuous layout (`Layout/ContinuousLayout.swift`, `Layout/ContinuousSpan.swift`):
- Tab ties: `ContinuousSpan.string` (one-based). `resolveTabTie` resolves each end independently and checks the string and the fret. The fragments follow the string line with 0.3 space of clearance and report `strings`, `from` and `to`. Tab voltas are accepted.
- Anchored lyric extenders: `ContinuousSpan.syllableId` names an `Annotation` (by `id`) on the source note. `format()` resolves it before each reflow. The extender takes the baseline and the ink edge of that syllable, and the staff envelope of a continuation row includes it. Lyric and hyphen labels use `Annotation.lyric`.

`PublicationView.insetStaff` carries `showTimeSignature`.

## 5.6.1

- `Clef`: a TAB clef selects the four-string glyph on a four-line stave and the six-string glyph otherwise, sits on the middle line, and is scaled so that its ink fits between the outer strings with a stroke width plus 1/24 of the span clear at each end (with one correction for hinting). `getGlyphY()` gives the shared baseline for drawing, ink and the inline `ClefNote`. `setType` refits a TAB clef that has a stave.
- `ClefNote.setStave(_:)` passes the stave to the clef and remeasures the width of a TAB clef.
- `Stave.getYForDrawnLine(_:)`: the drawn line center (with the half-pixel stroke alignment). The line drawing uses it. `setNumLines(_:)` refits the clefs and marks the stave unformatted.
- `TabStave.getYForGlyphs()`: halfway between the outer strings for every string count.
- `TimeSignature`: on a tab stave with the default lines, numeric, common and cut meters center their ink on the strings (`baselines(_:)`, used by `drawAt`, `getInkBounds` and `getBoundingBox`). `getBoundingBox()` of a single-row numeric meter returns the top box.

## New public API

`Note.writtenDots`; `StaveNoteStruct.restLine`, `StaveNote.restLine`, `StaveNote.setRestLine(_:)`, `StaveNoteError.badRestPosition`; `Stave.getYForDrawnLine(_:)`, `Stave.setBoundaryModifiers(_:notePadding:)`; `Clef.getGlyphY()`; `ClefNote.setStave(_:)` override; `StaveSection.getBoundingBox()`; `ContinuousSpan.string`, `.labelFontSize`, `.syllableId` (and the init parameters); `ResolvedSpan.syllable`; `PublicationOptions.noteHooks`; `EasyScoreStaffState.showTimeSignature`, `EasyScoreStaveSpec.showTimeSignature`, `EasyScoreMeasureSpec.showTimeSignature`, `.endBarline`, `.chords`, `.verses`; `EasyScoreLeadMark`, `EasyScoreLyricMark`; `VexCategory.fretDiagram`.

## Swift deviations

- `PublicationOptions` holds closures (`noteHooks`). It stays `Equatable` (`==` compares the hook count and the other fields) and becomes `@unchecked Sendable` (a publication renders synchronously).
- `StaveNote(_:)` does not throw. An invalid `restLine` (not a rest, or not finite) sets `staveInitError = .badRestPosition`; `setRestLine(_:)` throws `VexError("BadArguments", ...)` as upstream.
- `EasyScoreMeasureSpec.endBarline` is a `BarlineType`, so only `repeatBegin` can be rejected (upstream also rejects values outside the enum).
- The upstream regular expression for the first font family (`/^\s*(?:Bravura|"Bravura"|'Bravura')\s*(?:,|$)/i`) is a small string check.
- `ContinuousLayout.lyricBaseline` and the extender ink use `Annotation.computeX()`/`computeY()`, which throw in Swift; on an error they fall back to the top line (upstream would throw).

## Not ported

- Browser-only parts: the gallery, the guide, the PDF score library and the `tests/scores/*.js` viewer.
- The two-backend checks of the node tests (Canvas and SVG) run on the SVG string context only.

## Library fix found by the new parity cases

- `Formatting/Beam.swift` (`generateBeams`): the "unbeamable duration" check parses `durationToken` (the duration as written). Upstream `parseInt(note.getDuration(), 10)` is NaN for `"q"`, so a quarter note does not split an automatic beam group. Swift parsed `"4"`. Found by the Ballade (bar 2); no other parity case changed. This is an old divergence, not a 5.5–5.6 change.

## Observations

- `TabStave(options:)` with options that do not set `numLines` gets `StaveOptions`' five lines; upstream spreads the options over a six-line default. The parity cases pass `numLines: 6` explicitly. Not changed in this pass.
- `Articulation.Draw_Is_Idempotent` (parity suite) records expectation failures before and after this pass; it is not related to these releases.
