# Port notes: VexFlow 5.2.0 → 5.3.0

Upstream range: `git -C ../vexflow log 5.2.0..5.3.0` (release notes: `changelog/CHANGELOG.md`, section 5.3.0 "Engraving").

## Ported

### New modules (`Engraving/`)
- `src/engravingprofile.ts` → `Engraving/EngravingProfile.swift`: `EngravingProfile(musicFont:metadata:beamThickness:clearance:) throws`, `init(musicFont:metadataJSON:...)`, `stemAnchor(_:direction:) -> EngravingAnchor?`, `beamThickness`, `clearance`, `musicFont`. Errors: `EngravingProfileError` (`missingMusicFont`, `invalidDistance`; upstream `RangeError`). The metadata is used only when its `fontName` equals `musicFont`. Invalid optional font fields fall back (0.5 staff spaces, no anchor); invalid explicit values throw.
- `src/engravinggeometry.ts` → `Engraving/EngravingGeometry.swift`: `measureEngraving(_:options:) throws -> EngravingGeometry` (also `Flow.measureEngraving`), `EngravingShape`, `EngravingPoint`, `GeometryOptions` (`extension`, `paddingPx`, `viewport`), `GeometryDiagnostic` (codes `UnsupportedGeometry`, `UnformattedGeometry`, `InvalidGeometry`, `LayoutOverflow`). Participants are matched by exact class, as upstream. It only throws for invalid padding (`EngravingGeometryError.invalidPadding`).

### SMuFL metadata
Upstream does not load or embed font metadata: the caller passes the parsed `metadata.json` of an installed font (the tests read `node_modules/@vexflow-fonts/<font>/metadata.json`). The Swift port bundles the subset that `EngravingProfile` reads (`fontName`, `fontVersion`, `engravingDefaults`, `glyphsWithAnchors`) for Bravura 1.392, Petaluma 1.065 and Leland 0.77 as `Resources/smufl/<font>-metadata.json` (48 KB, 36 KB, 10 KB). `tools/extract_smufl_metadata.py` regenerates them from `../vexflow-5.4.0/node_modules/@vexflow-fonts`. License: SIL OFL 1.1, the same license texts as the bundled fonts (`Resources/fonts/licenses/{bravura,petaluma,leland}-LICENSE.txt`); sources and copyrights are in `Resources/smufl/NOTICE.txt`. API: `EngravingProfile.bundledMetadata(for:)`, `EngravingProfile.bundled(musicFont:beamThickness:clearance:)`, `EngravingProfile.bundledMetadataFamilies`. Profiles never use the bundled data unless the caller asks for it, so the default behavior is the same as upstream.

### Behavior changes in existing modules
- `StaveNote`: `StaveNoteStruct.musicFont`/`engraving` (also on `GraceNoteStruct`); `engraving` property; stem x and stem y bounds from SMuFL anchors when the head font is the profile font; multi-column unison heads (`NoteHead.displacementColumn`, `getDisplacementX()`), displacement flags set from sorted key props, `getVoiceShiftWidth`/`calcNoteDisplacements` with extra columns; more than three visible voices are placed in columns (`StaveNote.format`); the two-voice swap uses the actual pair; `getHeadInk()`, `getFlagInk()`, `getStemSegment()`, `getLedgerLines()` (ledger lines enclose all heads on a line), `getNoteHeadBounds(layoutX:)`.
- `Stem`: `getSegment(x:adjustment:)`, `isVisible()`, `getBoundingBox()` (was `nil`).
- `Element.getTextInk(_:_:)`.
- `Beam`: `renderOptions.contourSlope`, profile-driven `beamWidth` (explicit values still win), half-space snapping of level contour beams, `clearOtherVoiceHeads()` (multi-voice clearance through `TickContext.through`), `getStrips`, `getBoundingBox()` (strips only), `resetLayout()` (called by `Formatter.format`). Beam lines now draw an `end` of 0 (upstream checks `undefined`, not falsy).
- `TickContext.linkTimeline(_:)`, `through(_:)` (Formatter and ProportionalFormatter link the musical order).
- Optical spacing: `MeasuredSpacing` (`.proportional(ProportionalSpacing)`, `.optical`), `FormatterOptions.spacing`/`SystemFormatterOptions.spacing` are now `MeasuredSpacing?`. Error code `InsufficientOpticalSpace`.
- `Accidental.getInkBounds()`, `Dot.getInkBounds()` (rest dot shift no longer accumulates: `restShiftY`), `Articulation.getInkBounds()` (`setBetweenLines` survives `reset()`), `Ornament` side offset no longer accumulates in `xShift`; ornament y shift no longer accumulates; `Ornament.getBoundingBox()` includes both auxiliary accidentals.
- `Tuplet`: `TupletOptions.displayRatio`, `setRatioed` re-resolves glyphs, bracket clearance from articulation/ornament ink and annotation ink, `getBoundingBox()` positions first. `ModifierContext.getUnmeasuredTextLines(_:)`.
- `GraceNoteGroup`: new `format` (before/after groups on separate sides), after-group placement, `getLayoutElements()`, one retained slur per endpoint pair with `firstXShift`. `GraceNote.getSlash()`.
- `Curve`: `CurvePosition.auto` (new default), opening direction attaches beyond the stem tip on the stem side, `getAnchors()`.
- `StaveTie.getRibbonBounds()`.
- `Bend.format`: bends grouped per chord and sorted by string; `drawWidth` no longer mutated by draw.
- `KeySignature` glyphs use the key signature font; `TimeSignature.setMusicFont(_:)`.
- `Factory`: `FactoryOptions.engraving`; notes, grace notes, accidentals, articulations, clefs, key and time signatures use the profile music font.
- EasyScore composition: `.note(_, id:, stave:, grace:)` with `EasyScoreGraceGroupSpec`/`EasyScoreGracePitchSpec`/`EasyScoreGraceAccidental`/`EasyScoreGraceSide`; `EasyScoreCompositionSpec.graceAccidentals` (`EasyScoreGraceAccidentalPolicy.explicit/.ordered`); ordered key-aware accidentals per attack (`orderedAttacks`).

### Bug fixes found by the new tests
- `Element.setOriginX/Y` used the parameter `x`/`y` where upstream uses `this.x`/`this.y`. A reformat after a draw moved articulations by their drawn position. This fixes `Articulation.Draw_Is_Idempotent` (90 px) and several 1 px articulation cases.
- `StaveOptions.topTextPosition` is now `Double` (upstream `number`; the Greensleeves demo uses 3.5).

## Swift deviations
- `NoteHeadStruct.displacementColumn` is `Int?`; a negative column is clamped to 0 (the initializer does not throw; upstream throws `BadArguments`).
- `Beam.clearOtherVoiceHeads` is skipped when a note has no tick context (upstream throws from `postFormat`, which does not throw in Swift).
- `StaveTie` validates all ribbons before it opens the SVG group (upstream yields them lazily).
- `TupletOptions.displayRatio` is a `(numerator:denominator:)` tuple, so a wrong length cannot occur.
- `Accidental/Articulation.getInkBounds()`, `StaveTie.getRibbonBounds()`, `Curve.getAnchors()`, `GraceNoteGroup.getLayoutElements()`, `GraceNote.getSlash()` throw for unformatted input; `measureEngraving` reports them as `UnformattedGeometry`.

## Not ported (reason)
- `tests/engraving/*` (score persistence studies, M1 passage, VF6 notes), `tests/node/local-engraving-tests.mjs` (puppeteer with web fonts), the browser and raster parts of `engraving-layout-tests.mjs` (fresh-process reload, PNG ink scan, puppeteer SVG), `audit-dependencies-tests.mjs`, gallery HTML (`tests/all.html`, `tests/flow.html`), `rendering-tests.mjs` fixture kinds: browser, Node or tooling only. The raster ink test is replaced by a head/stem containment test and a draw-invariance check.

- `swift test --scratch-path .build-port --skip UpstreamSVGParityTests`: 939 tests pass (3 known issues from before).

## Parity results (no 5.3.0 references; compared with 5.4.0)
- Existing cases, over 0.1 px: 162 before → 118 after (`rows` 6 → 6, `struct` 13 → 13, `>1` 95 → 77, `<=1` 48 → 22). 54 cases improved, for example `Bend.Reverse_Bends` (28 px → 0.01), `Ornament.With_Upper_Lower_Accidentals` (50 px → 0.08), `Three_Voice_Rests.Three_Voices____2_Complex` (13 px → 0.06), `Formatter.Vertical_alignment___many_mixed_elements` (33 px → 0.4; Gonville 7.7, known Gonville text height), `Grace_Notes.Grace_Note_Basic`, `Articulation.Draw_Is_Idempotent` (exact).
- 3 cases changed for the worse, all under 0.1 px: `Ornament.Ornaments.Gonville` and `Ornament.Ornaments_Vertically_Shifted.Gonville` (0.04 → 0.08) and `ChordSymbol.Chord_Symbol_With_Modifiers.Petaluma` (0.079 → 0.083). They are pointer-rect widths: the note box now merges the ink-based ornament box (upstream 5.3.0 `Ornament.getBoundingBox`), and Gonville glyph metrics differ slightly.
- New demo cases (22 font runs): 13 within 0.1 px; Bravura/Petaluma at most 0.36 px; Gonville differences come from the known Gonville glyph widths (clef, vibrato, parenthesis, tempo note).
