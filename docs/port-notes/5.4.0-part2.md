# Port notes: VexFlow 5.3.0 → 5.4.0, part 2

Upstream range: `git -C ../vexflow log 5.3.0..5.4.0` (release notes: `changelog/CHANGELOG.md`, section 5.4.0).
Part 1 (`5.4.0-part1.md`) ported the changes to existing modules and the phrase, instrument and spelling modules. This pass ports the continuous layout, the system and page breaks, the score navigation and the publication, and connects the part 1 hooks. No `TODO(5.4.0 part 2)` marker remains.

## Ported

### New modules
- `src/systembreaks.ts` → `Layout/SystemBreaks.swift`: `chooseSystemBreaks(_:width:gap:indent:mode:)`, `BreakUnit`, `BreakConstraint` (`force`, `keep`), `SystemBreakMode` (`balanced`, `greedy`). Same dynamic program and costs.
- `src/pagebreaks.ts` → `Layout/PageBreaks.swift`: `paginate(_:_:)`, `PrintableSystem`, `PageConstraints`, `PageBreak`. Same cost order (forbidden turns, pages, penalty) and the same gap justification.
- `src/continuousspan.ts` → `Layout/ContinuousSpan.swift`: `ContinuousSpan`, `ContinuousSpanKind`, `ContinuousSpanSide`, `SpanAnchor`, `ResolvedSpan`, `SpanFragment`, `SpanFragmentPart`, `spanLabel(_:)`, `spanAbove(_:)`, `continuationPitch(_:_:_:)`, `fitSpan(_:_:)` (takes the fragment `inout`), `drawSpan(_:_:label:)`.
- `src/continuouslayout.ts` → `Layout/ContinuousLayout.swift`: `ContinuousLayout` (`hidden`, `isHidden(_:)`, `diagnostics`, `fragments`, `rows`, `format(_:) throws`, `draw(_:) throws`), `ContinuousOptions`, `ContinuousBoundary`, `ContinuousNavigation` (`segno(id:)`, `coda(id:)`, `dalSegno(target:)`, `toCoda(target:)`, `daCapo`, `fine`), `ContinuousSplitChord`, `ContinuousGroup`, `ContinuousRow`, `ContinuousDiagnostic`. All validation, rest compression, courtesy signs, tied-accidental arrivals, staff hiding, lane assignment, staff alignment (four refits), header labels, names, connectors, numbered rests, split stems and span fragments follow upstream in the same order.
- `src/scorenavigation.ts` → `API/ScoreNavigation.swift`: `ScoreNavigation` (`events`, `regions`, `diagnostics`, `hitTest(_:_:)`), `ScoreReadingEvent`, `ScoreHitRegion`.
- `src/publicationview.ts` → `Publication/PublicationView.swift`: `PublicationView`, `PublicationRegion`; internal `checkView`, `projectScore`, `insetStaff`, `restingMeasure`.
- `src/publication.ts` → `Publication/Publication.swift`: `Publication(_:)` with `render(_:) throws -> PublicationResult`, `PublicationOptions`, `PublicationPaper` (`a4`, `letter`, `custom`), `PublicationMargins`, `PublicationDiagnostic`, `PublicationPage` (`svg: SVGNode`, `number`, `systems`, `metadata`), `PublicationSystem`, `PublicationResult` (`pages`, `diagnostics`, `paper`, `toSVG(_:portable:)`, `toPrintHTML()`).
- New helper `Publication/SVGInk.swift`: the native replacement for the browser geometry (see below).

### Hooks connected
1. `Layout/Sheet.swift`: `setContinuousLayout(_:)`, `getContinuousLayout()`; `format()` delegates to the layout.
2. `API/Factory.swift`, `draw(retain:)`: skips the staves, voices, queued elements and systems in `hidden`, then draws each continuous layout after the systems.
3. `API/EasyScore/Composition.swift`: `EasyScoreCompositionSpec.continuous`; the `SignaturePolicy` diagnostic only without `continuous`; `starts`/`ends` staff states and the generated accidentals (`placed`) are recorded, and `ContinuousLayout` is installed inside the composition transaction (an invalid continuous spec rolls the composition back).
4. `Compatibility/Flow.swift` header lists `ScoreNavigation` and `Publication`.

### Change to an existing module (with reason)
- `Stave.setBoundaryModifiers(_:)` resets `startX` and the x of the begin modifiers and of the new boundary modifiers to the stave edge. `Stave.setX(_:)` also moves the boundary modifiers. Reason: the gated local patch in `Stave.format()` ("do not overwrite `modifier.x` or `startX` when they are already larger") kept the positions of the derived row-start signs after they were removed. A reflow to an earlier width then gave different measure widths. Upstream (and parity mode) recompute both in `format()`, so the reset changes nothing there. Recorded in `docs/local-deviations.md`.

## Native replacements for browser code
- Upstream draws into a hidden DOM host. Here each view is composed on its own `SVGRenderContext`. The pages are `SVGNode` trees, and `toSVG` returns strings, as upstream does.
- `inkBox()` (`getBBox()`, canvas `measureText()`, `transform.baseVal`) → `svgInkBox(_:)`: glyph ink of text from `TextMeasurer` (CoreText) with the inherited font attributes; the geometric bounds of path data with `CGPath.boundingBoxOfPath` (M, L, C, Q, A, Z; an empty path is a zero box at the origin, as in a browser); rectangles; the union for groups; `translate`, `scale`, `rotate` and `matrix` transforms.
- `label()` (`getBBox()` of page text) → `svgTextBox(_:)`: advance width and the font ascent and descent from `TextMeasurer`.
- The page-breaking (`splitRows` binary search on the row midlines) and the pagination (`paginate`) are unchanged.
- Registry: the default registry is turned off during `render` and restored after it, as upstream.
- PDF: upstream prints `toPrintHTML()` in a browser. Not ported. A CoreGraphics PDF writer fits next to `PublicationResult.toPrintHTML()`: a `CGContext(consumer:mediaBox:)` PDF context, one PDF page per `PublicationPage` with a media box of `paper` × 72 / 25.4 points, drawing each page's SVG tree through a CoreGraphics `RenderContext` scaled by 72 / 25.4 from millimeters. The header of `Publication.swift` says the same.

## Swift deviations
- There is no DOM target: `Publication.render(_:)` returns the result (upstream `render(target, options)` replaces the target children). An earlier result never changes.
- `toSVG(_:fonts:)` → `toSVG(_:portable:)` and `toPrintHTML(fonts)` → `toPrintHTML()`: the outlines come from the fonts that laid out the page (as in the 5.1.0 SVG export port), so no font list is passed.
- `PublicationOptions` holds the `PublicationView` fields directly (upstream `extends`); `options.view` returns them.
- The upstream string unions are enums (`SystemBreakMode`, `BreakConstraint`, `ContinuousSpanKind`, `ContinuousNavigation`, `ContinuousGroup.Kind`, `PublicationRegion.Kind`, `PublicationPaper`), so the "Unknown break mode", "Unknown break constraint" and unknown-kind checks cannot fail and are not ported.
- `ContinuousLayout.hidden` is a `Set<ObjectIdentifier>`; use `isHidden(_:)`. `ContinuousLayout.format(_:)` and `draw(_:)` throw (upstream throws from inside). The layout copies the composition arrays and does not keep the composition, so a sheet can outlive it (upstream relies on garbage collection).
- `ContinuousRow` is a struct with the `SheetRow` fields and `sheetRow`; `SpanFragment` is a value type and `progress` is a tuple.
- `ContinuousOptions.courtesy` is a `Bool` with default `true` (upstream `courtesy !== false`).
- `ScoreNavigation(_:staves:sources:)` takes the composition staves; `ScoreNavigation(_:staffNames:sources:)` takes `(id, name)` pairs (upstream `Pick<EasyScoreStaveSpec, 'id' | 'name'>`). It throws `DuplicateID` and `BadArguments` as upstream.
- Page metadata is written in key order with a small JSON writer. The `stroke` and `bend` fields of a `NotationIdentity` are not written (the `kind`, `id`, `label` and `index` fields are).
- `nextView` is a locked counter.

## Not ported (reason)
- The browser print viewport and PDF printing (see PDF above).
- `font.ts` `FontLoadFailed` (part 1).
- 5.5.0 and later changes to these modules (later releases).

## Tests
`Tests/VexFoundationTests/Upstream54LayoutTests.swift` (19 tests, 21 cases, in 3 suites):
- Continuous score (`continuous-score-tests.mjs`, with `tests/engraving/continuous-studies.mjs` rebuilt in Swift): vocal phrase retains IDs and reunites at the original width (also with `upstreamParityMode`); balanced against greedy breaks; grand-staff cross-staff beam and wedge progress across redraw; silent staves, compressed rests and repeat barlines; `keep` and `force`; all span families split into first, middle and last; courtesy key, clef and meter and tied-accidental reflow; rest compression interrupted by navigation and atomic validation; split stem and arpeggio; instrument change width; the browser reflow test with the SVG backend and two font pairs; a sheet that outlives its composition (Swift).
- Publication (`publication-tests.mjs`, with `tests/engraving/publication-studies.mjs` rebuilt in Swift): score and cello part on A4 and Letter (the same page ranges as upstream: part `[16, 26]`, A4 `[12, 24, 26]`, Letter `[8, 20, 26]`; margins; system gaps; unique IDs; portable SVG without text and with the same metadata and system transforms; rests; cue and ossia regions); the extracted cross-staff voice and `ExcludedAnchor`; forced and forbidden turns, invalid regions and overflow diagnostics; `paginate` unit cases; the percussion part of `instrument-profile-tests.mjs` (exported notation identities).
- Score navigation (`tests/web/navigation.mjs`, `navigationContracts`): reading order of simultaneous voices, a ghost note and TAB, spoken accidentals, string and fret labels, hit test with a source and NaN; and (Swift) span regions per row and the event label of a continuous score.
- `sheet-tests.mjs` did not change from 5.3.0 to 5.4.0.

Skipped browser-only assertions:
- `continuous-score-tests.mjs`: the Canvas backend, browser font loading (`FontFace`), and the pixel buffers (the Swift tests compare the SVG output instead).
- `publication-tests.mjs`: printing in Chromium and counting PDF pages and `MediaBox` sizes (the Swift test checks the print HTML pages and `@page` size); "pagination reserves running text at the final page scale" (it injects a CSS rule that changes the computed font size of the page furniture; there is no style sheet natively); the `innerHTML` checks of two DOM targets (replaced by checking that an earlier result does not change).
- `tests/web/navigation.mjs` `diagnosticsContracts` (phrase-layout and `measureEngraving` codes in a browser; part 1 covers these codes) and the other `tests/web/*` browser qualification tests.

Results:
- `swift build --scratch-path .build-port`: no new warnings.
- `swift test --scratch-path .build-port --skip UpstreamSVGParityTests`: 978 tests pass (3 known issues from before).
