# Port notes: VexFlow 5.6.1 → 5.7.0

Upstream range: `git -C ../vexflow log 5.6.1..5.7.0` (release notes: `changelog/CHANGELOG.md`, section 5.7.0).
23 files in `src/` changed (+1132/-211). Five modules are new. The manifest (`docs/porting-5.x-manifest.md`) gives the Swift file for each upstream file.

## New modules

- `hairpintip.ts` → `Stave/HairpinTip.swift`: `NienteTip`, `nienteTip(_:_:_:_:)`, `nienteBounds(_:_:)`, `drawNienteTip(_:_:)`. The circle radius is 0.35 space. It sits outside the closed vertex.
- `splitstem.ts` → `Layout/SplitStem.swift` (internal): `linkSplitStem`, `splitStemFor`, `beamStave`.
- `chordspacing.ts` → `Layout/ChordSpacing.swift` (internal): `reserveChordSpacing(_:_:)` and the lead-chord mark.
- `continuousbeam.ts` → `Layout/ContinuousBeam.swift`: `ContinuousBeam` (public class, internal API) and `beamMembers`. The import cycle with `easyscore/composition.ts` and `continuousspan.ts` does not apply in one Swift module. `beamMembers` takes the composition arrays (`notes`, `staves`), because `ContinuousLayout` keeps the arrays and not the composition.
- `tiedbend.ts` → `Instruments/TiedBend.swift`: `TiedBendDrawing` (public), `layoutTiedBend`, `drawTiedBend` (internal).

## Changes to existing modules

- `Beam`: `FeatheredBeamDirection` (`.left`/`.right`), `BeamRenderOptions.feathered`, `BeamConfig.feathered` (`generateBeams` copies it). `BeamContinuation` (`left`/`right` edges with `x`, `levels`, `progress`) and `Beam(_:autoStem:continuation:)`. A beam with a continuation edge can have one note. New errors `badContinuationProgress` and `badContinuationEdge` (upstream `BadArguments`). `getBeamLines` continues the shared levels to the edge x. `getStrips` fans the secondary beams. `clearOtherVoiceHeads` samples the slope of each feathered strip and excludes all of the beam's own notes from the peers. `getStemSlope` is 0 when the first note is the last note.
- `Factory.Beam`/`BeamThrowing`, `EasyScore.beam`/`beamThrowing`, `EasyScoreElements.beam` and `EasyScoreAutoBeamOptions`: a `feathered` parameter.
- `StaveNote`: a split stem. Only the owner (the note in the native beam) has a stem. Neither note has a flag. `setStave` gives the owner stem the y bounds of both heads. `getBoundingBox` includes the shared stem. `shouldDrawFlag()` is `stem != nil && hasFlag()`.
- `StaveHairpin`: `HairpinRenderOptions.niente`. `renderHairpin` draws from the open end to the closed end. With a niente tip the two arms are separate subpaths, and the circle is a separate path. `getLayoutEdges` includes the circle diameter. `getBoundingBox` includes the circle and half the stroke. `FormatByTicksAndDraw` keeps all options (upstream `...options`).
- `ChordSymbol`: `getHorizontalInk()` (throws when it has no note) and a shared `originX`.
- `AlternatingTremolo`: one to four strokes; whole-note endpoints; strokes between two stemless whole notes; cross-staff strokes with stem extensions (`fillRect`); a pair check at draw time.
- `GuitarGesture`: `TiedBend`, `copyTiedBend(_:)`, `bendAmount(_: TiedBend)`. `copyBend` uses the shared phase check.
- `NotationSpelling`: `ChordHarmony`, `transposeChord(_:semitones:steps:)`, `chordText(_:)`.
- `ContinuousSpan`: kinds `.beam` and `.glissando`; `niente`, `bend`. `ResolvedSpan.beam`, `.bendLabel`. `SpanFragment.nienteTip`, `.bend`. `glissandoY(_:_:_:)`. `drawSpan(_:_:label:bendLabel:)` draws glissandi, tied bends and niente circles.
- `ContinuousLayout`: beamed eighth split chords (validated at each `format`); continuous beams (row pieces fitted before the ink measurement and placed after the staff alignment); glissandi; tied bends (adjacent events of one TAB voice, below the staff by default, on the lanes above); niente fragments; `continuationPadding` (was `tabTiePadding`) for incoming ties, beams and glissandi; chord spacing (the rows are laid out again until `reserveChordSpacing` makes no change).
- `SystemBreaks`: `BreakUnit.after`, added to the gap after the unit.
- `Sheet`: chord spacing in `format()` (end padding per system).
- `PhraseLayout`: `PhraseSyllable.elideWith` (the text becomes `text + Glyphs.lyricsElision + elideWith`); `PhraseLayoutError.invalidElision`; bridges use `beamStave`.
- `Composition`: `EasyScoreLeadMark(note:harmony:)`, `EasyScoreLyricMark.elideWith`. Chord annotations are marked for chord spacing.
- `ScoreNavigation`: bend labels ("Bend N semitones on string S", "Sustain and release tied string S"); only palm mutes and tied bends get technique labels (a tab tie without a bend no longer gets the palm-mute text). Span regions include the bend bounds and the niente circle.
- `Publication`: the page metadata of a tied-bend span has `bend` (the envelope).

## Swift deviations

- Module registries: `splitstem.ts` uses a `WeakMap` and `chordspacing.ts` a `WeakSet`. Swift stores a `SplitStemLink` (weak references) on each `StaveNote` and an `isLeadChord` flag on `Annotation`.
- `Beam` is not `final` any more, so that `ContinuousBeam` can override `postFormat`, `getStripBounds`, `getBoundingBox` and `draw`. Upstream passes the continuation object by reference and mutates its `x`; Swift mutates `Beam.continuation` (`internal(set)`).
- `EasyScoreLeadMark` is one struct with `text` and an optional `harmony` (upstream: a union). A mark with both is rejected ("Choose either chord harmony or literal text.").
- `reserveChordSpacing` keys the padding by `ObjectIdentifier(System)`.
- `ChordSymbol.getHorizontalInk()`, `NotationSpelling.chordText(_:)` and `transposeChord` throw. `ContinuousBeam.measureRow`/`placeRow` throw (they create the row beams).
- `PhraseSyllable.elideWith` that is not a string cannot occur; an empty or blank one throws `PhraseLayoutError.invalidElision` (upstream `RangeError`).

## Not ported

- Nothing in `src/`. The upstream browser and canvas checks (pixel buffers, `getExtentOfChar`, `getPointAtLength`) become checks of the SVG string and of the geometry.

## Tests

- New: `Tests/VexFoundationTests/Upstream57Tests.swift` (18 tests in suite "Upstream 5.7.0 port"): native and wrapped niente circles (with hit regions), beamed split chords (both stem directions, both beam owners) and their validation, continuous beams (one row and two, a forced break, a single attack with continued levels, rejected anchors, identical ink to a native same-measure beam), glissandi (both directions, a break, an intermediate row with a clef change), tied bends (phases, ratios, labels, reading order, publication metadata, five invalid inputs), harmony transposition and chord text, whole/four-stroke/cross-staff tremolos, broken and generated feathered beams, lyric elision through reflow, an invalid elision, and chord spacing in `Sheet` and in the continuous layout.
- Changed on purpose: `Upstream54Tests.tremoloDividesWrittenDurationWhileRetainingStrokesAndRejectsUnrelatedEndpoints` rejects 5 strokes (5.7.0 accepts four).
- `aTiedTabBendRisesOnceAndReleasesOnItsOwnStringAfterReflow` accepts one `RowOverflow` at 155 px. The upstream test runs in a browser. With node-canvas metrics, upstream 5.9.0 gives the same overflow (row width 169.4987 against 169.4999 here).
- Cross-check with upstream 5.9.0 in node (node-canvas, Bravura and Academico): the row sizes and fragment coordinates of `tiedBendStudy`, `continuousBeamStudy`, both `glissandoStudy` directions and the stem segments of `beamedSplitChordStudy` (up and down) are identical to two decimals.
- `swift test --scratch-path .build-port --skip UpstreamSVGParityTests`: 1015 tests pass (3 known issues).

## Parity

- 5.7.0 adds no visual test (`tests/*_tests.ts` did not change; the new studies feed node tests only). So there are no new parity cases and no changed ones.
- Against the 5.6.1 references (`VEXFOUNDATION_UPSTREAM_TAG=5.6.1`): 468 cases. The 3896 artifacts are byte-identical to the artifacts of the unchanged 5.6.1 port (same 979 issues, 8 `STRUCT` mismatches, all Gonville, missing glyphs). No existing visual test uses a 5.7.0 feature, so no difference was expected.
